## Fix 1: criteria table ordering (031500 + 121152)

### `migrations/20260714_031500_backfill_guideline_documents.ts`
Added a pre-create block at the very top of `up()` that creates every
`*_checks_criteria` table the CURRENT config expects, so Local API queries
issued during 031500 (and later 095159) resolve their criteria joins.

Critical correction over the naive plan: the block runs on the adapter **pool**
(`payload.db.pool.query`, autocommit), **not** `db.execute`. `migrate.js` wraps
`up()` in a transaction, but `loadStates`' `payload.find` calls run WITHOUT
`req` — on a separate pooled connection that cannot see uncommitted DDL.
Creating the tables via `db.execute` reproduced the original
`relation ... does not exist`. Pool-committed DDL is visible to all
connections, matching how push-managed dev DBs already had these tables.

Pre-created via a plpgsql `DO` block (idempotent, `IF NOT EXISTS`):
- enum `enum_heuristic_criterion_expected` (guarded by `pg_type` check)
- 15 non-version criteria tables (`id`/`_parent_id` varchar) for parents:
  `guideline_docs_checks`,
  `guideline_docs_blocks_{column_unit,media_showcase,color_palette,do_dont}_checks`,
  `guideline_sections_checks`, `section_{cu,ms,cp,dd}_checks`,
  `guideline_pages_checks`,
  `guideline_pages_blocks_{column_unit,media_showcase,color_palette,do_dont}_checks`
- 15 version criteria tables (`id` serial, `_parent_id` integer, `_uuid`
  varchar): the `_..._v_..._checks` variants of the same 15 parents
- For each: FK `_parent_id -> parent(id) ON DELETE cascade` (wrapped in
  `EXCEPTION WHEN duplicate_object`) + btree indexes on `_order` and
  `_parent_id` (`<table>_criteria_order_idx`, `<table>_criteria_parent_id_idx`).

Legacy criteria table cleanup (review fix, commit `3ec676c20`): `DROP TABLE
parent CASCADE` only removes the child's FK constraint — it does NOT drop the
child table. Without explicit drops, the 20 pre-created legacy criteria tables
(10 non-version + 10 `_..._v`) would remain as empty orphans after 040034 and
break 121152's `down()` (enum dependency). Fix: 040034 now runs
`DROP TABLE IF EXISTS ... CASCADE;` for all 20 legacy criteria tables right
before the legacy parent drops; `guideline_docs*` / `_guideline_docs_v*`
criteria tables are never touched. `IF EXISTS` keeps it safe if re-run against
already-applied DBs (where it is recorded and never re-runs anyway). The 031500
comment claiming CASCADE cleanup was corrected to reference the explicit drop.

## Caveat for production
`hd_cms_prototype` and other dev DBs already recorded all these migrations in
`payload_migrations`, so the edited `up()` bodies never re-run there — the
fixes only change fresh-chain behavior. On a truly fresh production DB the
contrast checker seed is skipped (no `color-pairing` content exists to attach
it to); if real guideline content is later imported, `checker.contrast` /
`color.contrast` must be added manually or via a new migration.
