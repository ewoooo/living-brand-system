# 08. 접근성과 다국어

이 문서는 Creator UI와 Payload Admin 확장 화면에서 지켜야 할 접근성(a11y)과 다국어(i18n) 기준을 정리합니다.
초기에는 구현 체크리스트보다 설계 기준과 작성 위치를 정의합니다.

## 1. 적용 범위

| 대상 | 기준 |
| --- | --- |
| Creator UI | 현장 작업자가 사용하는 제작, 조회, 질문, 검수 화면에 적용합니다. |
| Payload Admin 확장 화면 | 기본 Payload Admin이 아니라 프로젝트에서 직접 추가한 관리 화면에 적용합니다. |
| 사용자 노출 문구 | 버튼, 안내, 오류, 검수 결과, Agent 답변 보조 문구에 적용합니다. |

Payload Admin 기본 기능은 Payload가 제공하는 기본 접근성, 번역 체계를 우선 사용합니다.

## 2. 접근성 기준

- 키보드만으로 주요 작업을 수행할 수 있어야 합니다.
- 입력 필드는 label, 설명, 오류 메시지를 화면 리더가 읽을 수 있게 연결합니다.
- focus 상태는 시각적으로 확인 가능해야 합니다.
- 색상만으로 상태를 구분하지 않습니다.
- 검수 실패, 저장 실패, Agent 실행 실패처럼 사용자가 조치해야 하는 상태는 텍스트로 설명합니다.

## 3. 다국어 기준

- 초기 릴리스는 한국어를 기본 언어로 합니다.
- 사용자 노출 문구는 화면 컴포넌트에 직접 박지 않고 `src/lib/messages` 또는 i18n 모듈에서 관리합니다.
- 내부 로그 메시지와 사용자 노출 메시지는 분리합니다.
- 날짜, 시간, 숫자, 파일 크기처럼 지역화가 필요한 값은 표시 직전에 포맷합니다.
- 실제 다국어 요구가 생기기 전까지 locale routing과 번역 관리 시스템은 만들지 않습니다.

## 4. 구현 위치

| 구현 대상 | 위치 |
| --- | --- |
| 사용자 노출 메시지 | `src/lib/messages` 또는 i18n 모듈 |
| 공통 UI 접근성 보완 | `src/components` |
| 기능별 문구와 상태 | `src/features/<feature>` |
| 날짜, 숫자 포맷 | `src/lib` |

## 5. 점검 항목

| 항목 | 확인 기준 |
| --- | --- |
| 키보드 조작 | 마우스 없이 주요 작업을 완료할 수 있습니다. |
| 오류 전달 | 오류 원인과 다음 행동을 텍스트로 확인할 수 있습니다. |
| 문구 관리 | 사용자 노출 문구와 내부 로그 문구가 섞이지 않습니다. |
| 지역화 포맷 | 날짜, 시간, 숫자 표시가 하드코딩되지 않습니다. |
